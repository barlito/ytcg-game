# packages/client

React 19 + Vite 8 client (`@colyseus/sdk`). Minimal playable board, « Violet Arcade » tokens mirrored from ytcg in `src/styles.css`.

- `catalog.ts` bundles the same `data/` JSON as the server (`import.meta.glob`) and reuses the engine (`describeCard`, `describeLocation`) for card text — never duplicate a rule or a text here.
- `useDuel.ts` owns the SDK connection: create / join by code / send / leave, reconnection token in `sessionStorage` (a refresh goes back into the game; guarded against StrictMode double effects).
- Friend code (3 letters): `lib/roomCode.ts` `normalizeRoomCode` (uppercase, no spaces / dashes) is applied while typing in `PlayActions` and again before `joinById`; the lobby shows it large and copiable on tap.
- The server message is the source of truth; local state is UI only (selected card, log). Each message is logged once (`useGameLog`).
- Cards (`components/card/`): `CardFace` (a `CardView`) and `CardPlate` (plain values, used by `DefinitionFace`) are a light port of the ytcg card (artwork from `${VITE_YTCG_URL ?? 'https://ytcg.youlz.fr'}/uploads/cards/<image>`, mat, neon line, rarity glow, hover tilt through CSS variables in `lib/hoverTilt.ts`, no React render per frame). `CardButton` is the focusable shell (tooltip, replay float, drag handle). Sizes use container units (`cqi`).
  - « Biseau verre » band (`CardBand.tsx`, `styles/card-band.css`): mana hexagon / rarity glyph (`rarity.ts`, unique = « ✦ 1/1 ») / power shield (green renforcée, red affaiblie from `power.ts`), effect text with the status keyword in pink (`effectText.ts`, wording from `describeCard`). `size` prop: `full` (hand, spotlight, drag overlay, large deck previews: text), `compact` (board, grids: no text, drops to mini under 76 px of card width by container query), `mini` (power only). Other props: `fresh` (cyan outline), `dim` (not owned any more), `CardBack` (real ytcg `card-back.svg`, `rarity` keeps the glow). Status pills are magenta mono on the left edge; legendary / unique get the 5 s holo sweep (off in reduced motion). The hand cards print their text: width `--hand-card` (`:root` in `board.css`, also the drag overlay), bounded by the width (capped at `max((min(100vw, 120rem) - 33rem) / 6.8, 150px)` so seven cards barely overlap in the hand column, `104px` floor of the clamp), the height and the height left under the locations (the board + hand fit the viewport without scroll down to ~1366×768), 84 px (compact cards, no text) under 900 px wide with horizontal scroll; the hand is a fan (`lib/fan.ts`, ±7°, playable cards raised, too expensive ones at 60 %) and overlaps just enough to fit (`data-count` → `--n`, margin computed from `100cqi`). The band grows upward with its text (`min-height` = the design height, fixed slant in cqi so the bevel and neon line stay aligned) and the text size steps down by length (`effectTier` in `effectText.ts`, `data-tier` on `.tband__text`: ≤ 90 chars 5.1cqi, ≤ 130 4.4cqi, longer 3.8cqi, never under 6.5px): the text always fits, checked on every catalog card. The card name is Pirata One at the top of the frame, the universe name at the top right (full size only), like the ytcg frame; `fresh` is set on `PendingCard` (your face-down cards of this turn, straight from `yourPending`).
- UI primitives (`components/ui/`, `styles/ui.css`, tokens in `styles.css`): buttons are classes (`btn-arcade` = primary parallelogram, `btn-ghost` = secondary, `btn-lg`, wrap in `btn-glow` for the violet glow); `<Notched tone>` cut panel, `<Chip tone active solid>` mono pill, `<Progress value tone label>` slanted bar, `<Toast title tone floating>`, `<Logo variant="hero|nav">` (7c; the YOUL wordmark is the untouched ytcg file seen through a window). Sides: `--side-you` cyan, `--side-opponent` magenta. Focus ring is global (`:focus-visible`).
- Large screens: the root font size grows with the viewport (`html` in `styles.css`: 16 px up to ~1780×1000, `min(0.9vw, 1.6vh)` above, capped at 36 px), so size layout, fonts, badges and panels in `rem` (board max width `120rem`, log column, deck thumbnails, editor) and keep `px` for media queries and hairlines. Board cards follow the location width (4 per side), the spotlight `min(26vw, 36vh)`.
- Drag & drop (`@dnd-kit/core`, `components/dnd/`): rules in `dnd.ts` (pure, tested) read `view.playableCards` / `view.openLocations` — never recompute a rule. Mouse drags after 6 px, touch after a 180 ms press, so taps stay clicks (click-to-select + « Poser ici » is the keyboard path).
- Replay (`animation/`): `queue.ts` (steps + durations), `scene.ts` (what the replay hides or animates on top of the final view), `placements.ts` (last spot of destroyed cards, drawn as ghosts). `useReplay` adjusts its state during render when a new message arrives (no setState in effects). Reduced motion = no replay, no spotlight.
  - Spotlight: each `cardRevealed` / `locationRevealed` becomes two steps, a `spotlight` step (`SPOTLIGHT_MS` = 4.4 s, `scene.spotlight`, `scene.current` null, the card stays face down on the board) then the landing step (its effects; the location tile flashes). `Spotlight.tsx` + `components/spotlight/`: overlay with the rarity halo and « Révélations · Tour n », the card rises face down then flips (rotateY, real card back), the effect panel slides in (« X révèle », Pirata One name, rarity · universe · place, « Effet déclenché », power counter), then the card shrinks to the board element found by `data-uid` / `data-location-header` (CSS variables set in a ref callback; keyframe percentages in `spotlight.css` follow the handoff timeline). The counter (`useCountSteps`, 120 ms per step) runs from the printed power to `revealedPower` (printed + the `powerChanged` events of this reveal, from `scene.unplayed`; pure, tested). It never catches the pointer; « Passer l’animation » (bottom centre) empties the queue.
  - The journal hides the lines of events not landed yet (`scene.unplayed`, `loggedCount`): it never spoils a reveal.
- Board (`Board.tsx`, `styles/board.css` / `locations.css` / `hand.css`): `StatusBar` is the top bar (opponent, turn tracker, timer, Journal button that opens the `EventLog` panel), `LocationColumn` = opponent row (bottom aligned) + `LocationHeader` notched tile (two score hexagons, solid + glowing for the leader, tint = terrain owner) + your row (empty slots complete the 4, the first becomes « Dépose ici » while a card can land), footer = `PlayerPanel` (energy gems) + `HandBar` + `TurnActions` (toast = last journal line, redraw, end of turn). Leads and verdicts come from the engine (`lib/lead.ts`, the final `view.result`).
- End of game (`ResultBanner.tsx`, `components/result/`, `lib/endgame.ts`, `styles/result.css`): full-screen result over the board (« Voir le plateau » folds it into a bar, « Partie terminée » stays in the top bar). Rows, totals and the winner come from `view.result` (never recomputed); the decisive card is the strongest card of the winner on a location the winner took (first on a tie, none for a draw). The total counts up in pure CSS (`@property --n`). No rematch, rank or PR: none exists.
- Tooltips render in a portal (`Tooltip`, `useTooltipAnchor`: hover, focus-visible, tap). The anchor is an element in state, not a ref read during render (React Compiler lint).
- Decks (`ytcg/`, `decks/`, `components/decks/`): the home loads `GET /api/duel/collection` then `/api/duel/decks` (`ytcg/session.ts`, `credentials: 'include'`, base `VITE_YTCG_URL`, default the page origin — the game is served on the ytcg domain). `ready` → deck list + editor, join options `{ deckId }`; `login` (401) → « Se connecter sur Youl TCG » link to `loginUrl`; `offline` (network, timeout, non-JSON page, 404 flag off) → the random-deck dev flow in `import.meta.env.DEV` (`make deploy` works without ytcg), an « indisponible » notice in a production build (the prod server only accepts ytcg decks).
  - Pure logic, tested: `ytcg/api.ts` `interpretResponse` (status + body → result), `decks/draft.ts` (editor reducer, payload, `draftStatus` = the server's `gameRuleRefusal`), `decks/curve.ts` (histogram + engine `deckCurveChecks` lines — never re-implement the curve), `decks/violations.ts` (ytcg 422 `violations`: `name`, `terrain`, `cards`, `cards[i]` → the card id at index i of the list SENT), `decks/pool.ts` (owned cards ∩ game catalog, terrains apart, universe/cost/tag filters), `decks/deck-state.ts` (playable / incomplete / game rules).
  - The editor lists owned cards known to the game only (`DefinitionFace` = the hand card from a definition), 12 cards + optional owned terrain; a saved card lost since or unknown to the game stays listed until removed.
- Home and deck builder (`components/nav/AppNav.tsx`, `components/home/`, `styles/nav.css`, `home.css`, `editor.css`): `HomeShell` = header nav (Arène / Decks / « Classement » disabled « bientôt » / « Collection ↗ » to `${ytcg}/collection`, pseudo + avatar only when known — the dev flow) and the 4-entry tab bar on mobile (none in the editor, which has its own bottom drawer). `Hero` = « Duel. » + play actions + `CardFan` (three real cards, `decks/showcase.ts` `pickFan`: active deck, else collection, else catalog; compact under 860 px). Deck tiles (`DeckTile`): cover = `deckCover`, pill from `deckBadge` (playable / N cartes manquent / engine refusal in the tooltip); a deck to fix opens the editor. Editor = filters column (`PoolFilters`: name search, universe chips, cost 1-6 boxes, tag chips) | grid | `DeckPanel` (count + `Progress`, 38 px lines, `CurvePanel` 1/2/3/4/5+ with the engine alert, `saveLabel` = why the button is disabled). The curve buckets are the engine's (5+ = `EXPENSIVE_FROM_COST`).
- Bundle: `Home` and `Board` are lazy; the first chunk only imports zod-free names from `@ytcg-game/server/messages` (types from `/protocol` are erased).
- Server URL: `VITE_SERVER_URL`, default `ws(s)://<host>:2567`. ytcg URL: `VITE_YTCG_URL` (API: default the page origin; artwork: default `https://ytcg.youlz.fr`). In production the client and server will sit on the ytcg domain behind Traefik (phase 4) so the `jwt` cookie reaches the server.
- Lint: function size limits apply to components too — split into small components.
